🖥️ Cliente (Front-end) — O que você VÊ

O que é? O navegador (Chrome, Firefox) do usuário.

O que faz?

  • Envia requisições HTTP (pedidos) ao servidor
  • Recebe respostas (HTML, JSON, imagens)
  • Renderiza a interface com HTML/CSS/JS

Analogia: Você no restaurante fazendo o pedido.

⚙️ Servidor (Back-end) — O que PROCESSA

O que é? Um computador remoto rodando Node.js.

O que faz?

  • Recebe requisições e identifica a rota
  • Aplica regras de negócio (validações, cálculos)
  • Consulta o banco de dados MySQL
  • Retorna a resposta em JSON

Analogia: A cozinha que prepara o prato.

🗄️ Banco de Dados MySQL — Explicado

Por que usamos um banco? Onde os dados ficam guardados de forma permanente.

┌── usuarios ──────────────┐
│ id INT (PK) ← gerado auto │
│ nome VARCHAR(100) │
│ email VARCHAR(100) UNIQUE │
│ senha VARCHAR(255) │
└────────────────────────────┘
        ↑ 1 usuário tem N pokémons
┌── pokemons ─────────────────┐
│ id INT (PK) │
│ usuario_id INT (FK) → usuarios.id │
│ nome, tipo, nivel │
│ ataque, hp, sprite_url │
│ vitorias INT │
└──────────────────────────────┘

O que significa cada termo?

PK (Primary Key) — Identificador ÚNICO de cada linha. Nunca repete. O banco gera sozinho (AUTO_INCREMENT).

FK (Foreign Key) — "Conexão" entre tabelas. usuario_id em pokemons aponta para id em usuarios.

ON DELETE CASCADE — Se deletar o usuário, TODOS os pokémons dele são deletados juntos (não ficam órfãos).

UNIQUE — O email não pode repetir. Se tentar cadastrar o mesmo email, dá erro.

VARCHAR(100) — Texto com no máximo 100 caracteres.

-- Criar a tabela (rodar UMA vez) CREATE TABLE pokemons ( id INT AUTO_INCREMENT PRIMARY KEY, usuario_id INT NOT NULL, FOREIGN KEY (usuario_id) REFERENCES usuarios(id) ON DELETE CASCADE );

⚡ JavaScript Assíncrono — Cada Passo Explicado

Por que o JS precisa ser assíncrono? Porque buscar dados na internet DEMORA.

// ═══ O PROBLEMA ═══ // Sem async/await, isso acontece: const resposta = fetch('/api/pokemons'); console.log(resposta); // ❌ Imprime: Promise {pending} // Os dados AINDA NÃO CHEGARAM! // ═══ A SOLUÇÃO: async/await ═══ // "await" = ESPERE a resposta chegar // "async" = marca a função como assíncrona // Agora funciona na ordem certa! async function carregarPokemons() { // Passo 1: Pede os dados ao servidor // await FAZ O JS PARAR AQUI até receber const resposta = await fetch('/api/meus-pokemons'); // Passo 2: Converte a resposta em JSON // O servidor envia texto, .json() transforma // em objetos JavaScript manipuláveis const pokemons = await resposta.json(); // Passo 3: "pokemons" agora é um ARRAY: // [{nome:"Pikachu", ataque:55, hp:35}, ...] // Podemos usar .forEach para percorrer! }

O que cada coisa faz?

async — Declara: "esta função tem operações que demoram". Obrigatório para usar await dentro.

await — "Pare aqui e espere o resultado". Sem ele, o código continua ANTES dos dados chegarem.

fetch(url) — Faz uma requisição HTTP GET para a URL. Retorna uma Promise (promessa de dados futuros).

.json() — Transforma o texto bruto da resposta em objetos JavaScript que podemos usar.

Analogia do Delivery

🛵 fetch() = Você faz o pedido no iFood

⏳ await = Você espera o entregador chegar

📦 .json() = Você abre a embalagem

🍕 pokemons = A comida pronta para consumir!

🔌 Integração com PokeAPI — Como Fizemos

Nosso servidor Node.js busca dados na PokeAPI e repassa ao front-end. Veja cada etapa:

O Fluxo Completo (3 chamadas)

Front-end → GET /api/pokemon/descricao/pikachu → Nosso Server

Nosso Server faz internamente:
  1️⃣ fetch("pokeapi.co/api/v2/pokemon/pikachu")
     → Recebe: sprites, stats, tipos

  2️⃣ fetch("pokeapi.co/api/v2/pokemon-species/pikachu")
     → Recebe: descrição da Pokédex

  3️⃣ Combina tudo e retorna JSON ao front

Front-end ← JSON {sprite, descricao, stats...}

Por que o SERVER chama a API e não o front?

→ Segurança (esconde chaves de API)

→ Cache (pode salvar para não chamar toda vez)

→ Formatação (filtra só o que o front precisa)

Código do Servidor (simplificado)

// Rota que o front-end chama app.get('/api/pokemon/descricao/:nome', async (req, res) => { // 1. Busca dados na PokeAPI const pokeRes = await fetch( `https://pokeapi.co/api/v2/pokemon/ ${req.params.nome}` ); const poke = await pokeRes.json(); // 2. Busca descrição (outro endpoint) const specRes = await fetch(poke.species.url); const spec = await specRes.json(); // 3. Monta resposta com só o necessário res.json({ sprite: poke.sprites.other ['official-artwork'].front_default, descricao: spec.flavor_text_entries .find(e => e.language.name === 'en') .flavor_text, stats: poke.stats, tipos: poke.types.map(t => t.type.name) }); });

🌐 O que é uma API?

API (Application Programming Interface) é um contrato que permite dois softwares conversarem entre si.

Analogia: O Garçom

🧑 Você (Cliente) → 📋 Cardápio (Docs) → 🤵 Garçom (API) → 🍳 Cozinha (Servidor)

Você não vai na cozinha. O garçom (API) leva o pedido e traz a resposta.

Por que usar APIs?

  • Não reinventar a roda (dados já existem!)
  • Acesso a dados ricos e atualizados
  • Foco no seu produto, não na coleta de dados
  • Escalabilidade (a API aguenta o tráfego)

🔗 PokeAPI — Anatomia da Documentação

Link: https://pokeapi.co/docs/v2 — Abra ao lado para acompanhar!

Como ler a documentação

🌐 URL Base = o endereço raiz de todas as chamadas:

https://pokeapi.co/api/v2/

Tudo que vem depois é o endpoint.

📍 Endpoint = o caminho específico do recurso:

/pokemon/ → lista todos

/pokemon/pikachu → um específico

/pokemon/25 → pelo ID numérico

⚙️ Parâmetros = filtros na URL:

?limit=151 → quantos trazer

?offset=20 → pular os 20 primeiros

Exemplo completo:

/pokemon?limit=10&offset=0

Formato da Resposta (JSON)

// GET https://pokeapi.co/api/v2/pokemon/pikachu // A resposta é um OBJETO JSON enorme. // Precisamos saber NAVEGAR nele: { "name": "pikachu", ← texto simples "id": 25, ← número "types": [ ← ARRAY de objetos { "type": { "name": "electric" ← acesso: data.types[0].type.name } } ], "stats": [ { "base_stat": 55, ← acesso: data.stats[1].base_stat "stat": { "name": "attack" } } ], "sprites": { ← objeto aninhado "other": { "official-artwork": { "front_default": "https://..." ↑ acesso: data.sprites.other ['official-artwork'] .front_default } } } }

🔍 Filtrar por Tipo — Como e Por Quê

O conceito do filtro

Quando clicamos no botão "🔥 Fogo", passamos o texto 'fire' como argumento para a função.

A função percorre TODOS os Pokémons e verifica: "este Pokémon tem o tipo 'fire'?"

Se SIM → mostra. Se NÃO → esconde.

Fluxo visual

1. Clique: filtrarPorTipo('fire')

2. Percorre 151 Pokémons:
Bulbasaur [grass,poison] → ❌ esconde
Charmander [fire] → ✅ mostra
Squirtle [water] → ❌ esconde
Charizard [fire,flying] → ✅ mostra

3. Resultado: só cards de Fogo na tela

O código explicado

// ═══ ARRAY.FILTER() ═══ // .filter() cria um NOVO array contendo // apenas os itens que passam no teste. // // POR QUE .filter()? // Porque não queremos DELETAR os Pokémons, // só ESCONDER temporariamente. // O array original "todos" continua intacto. // Criamos um novo array "filtrados" só // com os que passam na condição. let todos = []; // todos os 151 function filtrarPorTipo(tipo) { // "tipo" = o argumento recebido // Ex: 'fire', 'water', 'grass' const filtrados = todos.filter(pokemon => { // pokemon.types = ['fire', 'flying'] // .includes(tipo) = contém 'fire'? // Se sim → TRUE → fica no array // Se não → FALSE → é removido return pokemon.types.includes(tipo); }); // Limpa a tela e mostra só os filtrados grid.innerHTML = ''; filtrados.forEach(p => { grid.innerHTML += `<div>...</div>`; }); }
