📚 Dados Locais vs API Externa

Entenda a diferença entre criar seus próprios dados e consumir APIs que já existem no mercado

Como programadores, temos duas abordagens: construir do zero ou integrar com serviços existentes

🎯 O que vamos aprender aqui?

🔨 Abordagem 1: Dados Locais (Hardcoded)

Você cria manualmente todas as informações dentro do seu código. Os dados vivem no servidor como constantes, arrays ou objetos JavaScript.

  • Controle total sobre os dados
  • Funciona offline (sem dependência externa)
  • Dados limitados ao que você escreveu
  • Manutenção manual para cada alteração

🌐 Abordagem 2: API Externa (PokeAPI)

Você consome dados de terceiros via HTTP. Uma API pública fornece informações atualizadas e completas sem que você precise criá-las.

  • Dados ricos e sempre atualizados
  • Milhares de registros disponíveis
  • Depende de conexão com internet
  • Pode ter limites de uso (rate limiting)

💻 Comparando o Código

DADOS LOCAIS server.js
// Os dados são escritos MANUALMENTE no código const DESCRICOES = { 'Pikachu': 'Quando vários destes Pokémon se reúnem, a eletricidade pode causar tempestades de raios.', 'Charmander': 'A chama em sua cauda indica sua força vital.', // Precisa adicionar CADA Pokémon manualmente // Se quiser 800 Pokémons = 800 linhas! }; // Rota simples: retorna do objeto local app.get('/api/pokemon/:nome', (req, res) => { const descricao = DESCRICOES[req.params.nome]; res.json({ descricao }); });
✅ Vantagens: Rápido, funciona offline, sem dependência externa, zero latência.
⚠️ Limitações: Apenas 7 Pokémons, dados podem ficar desatualizados, trabalho manual para cada novo registro.
API EXTERNA server.js
// Os dados vêm da PokeAPI (1000+ Pokémons!) app.get('/api/pokemon/:nome', async (req, res) => { // 1. Busca dados na API externa const pokeRes = await fetch( `https://pokeapi.co/api/v2/pokemon/ ${req.params.nome}` ); const data = await pokeRes.json(); // 2. Busca descrição (outro endpoint) const specRes = await fetch( data.species.url ); const specData = await specRes.json(); // 3. Retorna dados REAIS e COMPLETOS res.json({ sprite: data.sprites.other['official-artwork'] .front_default, stats: data.stats, descricao: specData.flavor_text_entries[0] }); });
✅ Vantagens: 1000+ Pokémons, dados completos (stats, habilidades, evoluções), sprites HD oficiais, sempre atualizado.
⚠️ Limitações: Precisa de internet, latência na resposta (~200ms), pode ficar fora do ar, limites de requisição.

🎓 Lição para o Programador

🔨

Crie do Zero

Quando os dados são seus (ex: cadastros de usuários, produtos da sua loja, conteúdo proprietário).

🌐

Use APIs Existentes

Quando os dados já existem (ex: clima, CEP, cotações, mapas, redes sociais, Pokémons).

🤝

Combine os Dois!

Na vida real, a maioria dos apps usa AMBOS: dados próprios no banco + dados de APIs externas.

💡 No nosso Pokémon Trading App usamos AMBOS:
  • Dados locais (MySQL): Usuários, coleção pessoal, trocas, vitórias → dados que NÓS criamos e gerenciamos
  • API externa (PokeAPI): Descrições, sprites HD, stats oficiais, cadeia de evolução → dados que JÁ EXISTEM e são mantidos por terceiros

🚀 Como Usar uma API Externa — Passo a Passo

1️⃣ Encontre a API

Pesquise APIs públicas no GitHub Public APIs ou busque no Google: "API de [tema]".

Ex: pokeapi.co, viacep.com.br, openweathermap.org
2️⃣ Leia a Documentação

Toda API tem docs explicando os endpoints, parâmetros e formato de resposta.

Ex: pokeapi.co/docs/v2 mostra todos os recursos disponíveis
3️⃣ Teste no Navegador

Cole a URL da API no navegador e veja o JSON de resposta. Entenda a estrutura dos dados.

Ex: cole pokeapi.co/api/v2/pokemon/pikachu no Chrome
4️⃣ Use fetch() no Código

No JavaScript (front ou back), use fetch(url) com async/await para consumir os dados.

Sempre trate erros com try/catch!
5️⃣ Extraia o que Precisa

A API retorna MUITOS dados. Navegue o JSON e extraia apenas as propriedades necessárias.

Ex: data.sprites.other['official-artwork'].front_default
6️⃣ Renderize na Interface

Use os dados obtidos para montar o HTML dinamicamente com JavaScript (DOM manipulation).

Ex: container.innerHTML += `<img src="${sprite}">`
